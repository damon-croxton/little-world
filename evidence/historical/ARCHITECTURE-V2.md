## Timing — authoritative shared rule
One logical **cycle** is one nominal simulation second at1x; this is a neutral sandbox time unit, not a day. State `tick` remains integer completed cycles for decisions, report ages and existing progression. Add state `step` integer motion pulses and `time` simulation seconds/cycles. `SIM_DT=0.1` seconds, 10 deterministic pulses/cycle.

`stepSimulation(state, steps=1)` now advances `steps` fixed0.1-second pulses. Each pulse increments step, sets time=step/10 and tick=floor(step/10). Core advances physical worker movement/harvesting EVERY pulse. `stepStrategy(state, dt=0.1)` advances physical scouts/armies/traders EVERY pulse, but decision, upkeep, diplomacy/attrition/report-age changes occur only on cycle boundary `state.step % 10 === 0`. Call `stepProgression(state)` only at cycle boundaries. Births/consumption/building investment/planning likewise once per cycle. Preserve one RNG stream, never render-time decisions. Pure step batches must match individual pulses exactly.

Before movement EACH pulse, core stores `prevX=x,prevZ=z` on every group. All moving groups have continuous fractional x/z. Renderer receives alpha (clock remainder divided bySIM_DT) and interpolates previous/current state. No per-day waypoint easing; no cumulative frame-based smoothing lag. Paused animation/activity must actually pause, except camera controls.

Lead clock advances fixed10Hz and preserves remainder. Main `window.littleworld.step(n)` remains developer-facing **cycles** for convenience (calls stepSimulation(state,n*10)); `stepPulses(n)` explicit raw interface. Renderer update signatures are expanded below.
